## Goal

Light up the **Wave-1 synthetic milestone cards** — the dopamine layer of the Recap feed. F0 already ships `b1GradePR`, `b3MostClimbs`, and `b5Streak` as composer recipes; F5 **adds the remaining Wave-1 cards as new `FeedComposer` registry recipes + new `FeedCardKind` cases** (`a3OnTheBoard`, `b2FirstAtGrade`, `b4LiftPR`) and **extends** the existing `b1`/`b5` recipes per the taxonomy, then ships the **card VIEWS** for each on Pulse Pro so they actually render in F1's stream. These are the cards that prove the feed "composes itself" — a fresh "V7 · YOUR HARDEST EVER" or "First V5 ever" or "Bench est-1RM PR" card floats into the stream the instant the underlying send/set is logged, degrading by absence everywhere the data is missing (`_locked-design.md:188`). **Keystone rule:** every new card is added as a registry recipe + a `FeedCardKind` case + a payload + a view — **never** by editing F0's ordering/recency-decay core (`_locked-design.md:228`, `FeedComposer.swift:112-130`). All eligibility predicates are pure and unit-tested before any pixel renders.

## Context the implementer needs

- **The keystone extension contract is already wired.** `FeedComposer.compose(...)` builds its `cards` array by appending one recipe's output at a time (`FeedComposer.swift:124-130`); F5 adds `cards += a3OnTheBoardCards(...)`, `cards += firstAtGradeCards(...)`, `cards += liftPRCards(...)` lines there and the matching private recipe funcs — the recency-bounded sort, the lens post-filter, and the window clamp are untouched. New cases go on `FeedCardKind` (`FeedCard.swift:14-22`); new payloads on `FeedCardPayload` (`FeedCard.swift:115-123`); a new `Salience` tier per card on the existing `Salience` enum (`FeedComposer.swift:94-101`). Do **not** add new top-level passes or touch `recencyDecay`/the sort in `compose`.
- **a3 On-the-Board** (`_locked-design.md:157`, taxonomy row a3) — eligibility: a session (or day bucket) has **≥1 `KilterLitEvent` AND no full session log** (the honest "pulled climbs up on the board but never logged an ascent" path). Source is the pure `KilterOnTheBoard.LitEvent` value mirror (`KilterOnTheBoard.swift:28-44`) — a plain mirror of the `KilterLitEvent` @Model (`KilterModels.swift:465-469`), already device-free. Add a `litEvents: [KilterOnTheBoard.LitEvent] = []` input param to `compose(...)` and a `KilterLitEventInput` bridge in `FeedInputs.swift`. Payload: `{litCount, gradeSpread}` (distinct grade labels lit). Category `.climbing`; salience just above a routine session, below a PR. The "no full log" guard joins lit events to `kilterLogs` by normalized `climbUUID` (`KilterClimbID.normalize`, `KilterOnTheBoard.swift:7-11`) within the day/session bucket — reuse that normalizer, do not write a new one.
- **b1 Grade PR — extend** (`_locked-design.md:158`). F0 already emits `b1GradePR` (`FeedComposer.swift:121`, `gradePRCards`) and the `GradePRPayload` exists (`FeedCard.swift:82-87`). F5's job is the **view + taxonomy extension**: render the celebratory "V7 · YOUR HARDEST EVER" card with accent halo (wireframe 9), and make sure the PR predicate diffs the new send's `difficulty` against the all-time `KilterAllTimeStats.maxGradeDifficulty` (`KilterAllTimeStats.swift:52`) — wire `previousGrade` into the payload if F0 left it nil. Do not duplicate the PR recipe; refine it in place if needed.
- **b2 First at Grade** (`_locked-design.md:159`) — eligibility: the **first-ever send at that grade band**. Pure log scan over `kilterLogs` (`KilterClimbLog`, `KilterModels.swift:247-298`): for each `.sent`/`.flash` log, if no earlier `.sent`/`.flash` log shares the same grade band (bucket on `gradeLabel`/`difficulty`), emit a `b2FirstAtGrade` card anchored at that send's date. New payload `FirstAtGradePayload {grade, climbName, difficulty}`. This is distinct from b1: b2 fires once per grade band ever, b1 only when the band exceeds the all-time max. Category `.milestone`.
- **b4 Lift PR** (`_locked-design.md:161`) — eligibility: **est-1RM or volume > prior best per `exerciseId`**. Both platforms have set data, so this is parity-safe. Source is `SetLog.actualWeight × actualReps` (`WorkoutModels.swift:317-340`) grouped by `SessionExercise.exerciseId` (`WorkoutModels.swift:345`). Use the **Epley est-1RM** (`weight × (1 + reps/30)`) as the pure per-set 1RM estimate; track per-`exerciseId` running best across the chronological set stream and emit a `b4LiftPR` when a completed set beats the prior best (guard: `actualWeight != nil`, `actualReps != nil`, `actualReps > 0`, `completedAt != nil`). Skip `disciplineRaw == running/timed` exercises (no weight). New payload `LiftPRPayload {exerciseName, est1RM, weight, reps, previousEst1RM?, unit}`. The composer's `WorkoutSetInput`/`WorkoutExerciseInput` already carry `actualReps`/`actualWeight`/`disciplineRaw`/`displayName` (`FeedComposer.swift:49-74`) — add `exerciseId` + `weightUnit` to those inputs and bridge in `FeedInputs.swift`. Category `.strength`, salience at the `gradePR` PR tier.
- **b5 Longest Streak PR — extend** (`_locked-design.md:162`). F0 emits a `b5Streak` card when the **current** streak ≥3 (`FeedComposer.swift:262`, `streakCards`). F5 extends it to a **PR variant**: when the current streak **beats the prior best** streak (a session-date scan over all sessions), promote it to the celebratory "longest streak ever" framing — protective/"Go Gentler" tone, never guilt (wireframe 12, `_locked-design.md:178`, §6.4 "Gentler-protective framing"). Add `isRecord: Bool` + `previousBest: Int` to `StreakPayload` (`FeedCard.swift:94-97`, additive) and keep the existing ≥3 baseline behavior; bump salience only for the record variant.
- **Card VIEWS on Pulse Pro** (`_locked-design.md:194` Pillar 1) — each new card kind gets a SwiftUI view built from `PulsePro.DisciplineHero`/`StatRibbon` (`PulsePro.swift:11`) + `.snappetCard()` (`SnappetCard.swift:28`) with the discipline edge accent (`SnappetColor.kilter` for a3/b1/b2/b5, `SnappetColor.workout` for b4). PRs (b1/b2/b4/b5-record) get the **accent halo / celebratory treatment** (wireframe 9). These slot into F1's existing card dispatch — F1 renders whatever `FeedComposer` returns, so F5 only adds the per-kind view branches, it does not touch `FeedView`'s scroll/lens/freshness machinery.
- **No HR, no media, no share, no detail-push in F5** — those are F2/F3/F4. F5 is purely "more synthetic card kinds + their flat card views." Detail views and share hints can set `shareHint` on the payload (e.g. `b1`→`.gradePRTicket`) for F4 to consume later, but F5 ships no `ShareComposer`.
- **Degrade by absence (`_locked-design.md:188`, §7):** every predicate is gated on its specific source field. a3 needs lit events; b4 needs completed weighted sets; none reference HR or `SessionMedia`, so all five compose identically on Android (this is the parity path FA4 ports verbatim against the golden corpus). No card is ever a stub or greyed button — absent data ⇒ card simply not emitted.

## Approach

- `Feed/FeedCard.swift`: add `case a3OnTheBoard`, `case b2FirstAtGrade`, `case b4LiftPR` to `FeedCardKind`; add `OnTheBoardPayload`, `FirstAtGradePayload`, `LiftPRPayload` structs + their `FeedCardPayload` cases; extend `StreakPayload` with `isRecord`/`previousBest` (additive) and `GradePRPayload.previousGrade` wiring if needed.
- `Feed/FeedComposer.swift`: add `litEvents` input param to `compose(...)`; add `exerciseId`/`weightUnit` to `WorkoutSetInput`/`WorkoutExerciseInput`; add private recipes `a3OnTheBoardCards`, `firstAtGradeCards`, `liftPRCards`; extend `streakCards` for the record variant; add the three `cards += …` lines (and nothing else) in `compose`. Add `Salience.onTheBoard`, `Salience.firstAtGrade`, `Salience.liftPR` tiers. Reuse `KilterClimbID.normalize` for the lit↔log join.
- `Feed/FeedInputs.swift`: add the `@Model → input` bridges — `KilterLitEvent`/`KilterOnTheBoard.LitEvent` → `KilterLitEventInput`, and the `exerciseId`/`weightUnit` fields on the existing workout bridges. (Bridges are not exercised by the pure tests.)
- `Feed/FeedMilestoneCards.swift`: the SwiftUI views — `OnTheBoardCardView`, `GradePRCardView` (celebratory halo), `FirstAtGradeCardView`, `LiftPRCardView`, and the streak-record treatment — each on `PulsePro` + `.snappetCard()` + edge accent. Wire them into F1's per-kind card dispatch.
- Pure predicate/aggregation logic (1RM estimator, first-at-grade scan, streak-record scan, lit↔log join) lives in the composer recipe funcs so it unit-tests with no simulator.

## Acceptance criteria

- [ ] `FeedComposer.compose(...)` emits `a3OnTheBoard` for a session/day with ≥1 lit event and **no** matching full log (joined via `KilterClimbID.normalize`), and never when a full log exists for that climb.
- [ ] `b1GradePR` renders the celebratory "YOUR HARDEST EVER" card with accent halo and a correct `previousGrade`; it fires only when the send's `difficulty` exceeds all-time `maxGradeDifficulty`.
- [ ] `b2FirstAtGrade` fires exactly once per grade band, on the first-ever `.sent`/`.flash` at that band, and not on subsequent sends in the band.
- [ ] `b4LiftPR` fires when a completed weighted set's Epley est-1RM beats the prior best **per `exerciseId`**; skips running/timed exercises and incomplete/zero-rep sets; payload carries `previousEst1RM` and the correct unit.
- [ ] `b5Streak` keeps the F0 ≥3 baseline and adds the record variant (`isRecord=true`, `previousBest` set) with protective/"Go Gentler" framing when the current streak beats the prior best.
- [ ] All new cards are added **only** as `FeedCardKind` cases + composer recipes + `cards += …` lines + views — F0's `recencyDecay`, the salience×decay sort, the window clamp, and the lens post-filter are unmodified (keystone rule).
- [ ] All cards degrade by absence (empty/absent source ⇒ card never emitted; no stubs); none reference HR or `SessionMedia`, so they compose identically for the FA4 Android port (golden-corpus-safe).
- [ ] Pure predicate tests pass with no simulator; app type-checks (Swift 6, 0 warnings); `decisions.md` updated for the Epley-1RM choice and the grade-band bucketing rule.

## Constraints

- On-device only; derive-on-read (no card persistence). Reuse `PulsePro`/`SnappetCard`/`SnappetColor`, `KilterAllTimeStats`/`KilterSessionStats`/`KilterOnTheBoard`, and `KilterClimbID.normalize` — no new brand tokens, no duplicate normalizer, no re-derived stats math.
- Cards added as registry recipes + `FeedCardKind` cases **only**; never edit F0's ordering/recency core. Extensions to `StreakPayload`/`GradePRPayload`/workout inputs must be **additive** (Codable backward-compatible).
- Eligibility inputs use **shared cross-platform fields only** (no iOS-only HR/media/per-climb-timing in any F5 predicate) so the Kotlin port reproduces the golden corpus verbatim. No device-burn items in this phase (no AVFoundation/Photos/share-sheet) — F5 is pure logic + flat views.
