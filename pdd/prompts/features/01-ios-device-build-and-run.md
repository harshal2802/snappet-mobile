# Prompt: First on-device build + run against real workouts → first feedback log (P1)

**File**: pdd/prompts/features/01-ios-device-build-and-run.md
**Created**: 2026-05-31
**Project type**: Native iOS feature (Swift / SwiftUI) — on-device runtime verification, not a code-only change.
**Chain**: `pdd/prompts/features/PLAN-ios-to-shippable.md` → P1
**Source**: [Snappet#60](https://github.com/harshal2802/Snappet/issues/60) §3 (completed-workout HR), §C (permissions), §E (feedback loop).
**Context**: `pdd/context/project.md`, `pdd/context/conventions.md`, `pdd/context/decisions.md`, [`ios/App/README.md`](../../../ios/App/README.md), [`ios/App/RUNBOOK-device.md`](../../../ios/App/RUNBOOK-device.md)

## Goal

Take the type-checked v0.1 MVP and **actually run it on a real iPhone against real Apple Watch
workouts** for the first time — the verification step that unblocks the entire chain. The deliverable
is not new features: it is *the running app plus the first `highlight-feedback.jsonl`* it produces,
and the fixes for any runtime / permission / HealthKit / Photos / AVFoundation issues that a
type-check provably cannot catch (see `decisions.md` 2026-05-30 — "type-check ≠ run").

This requires the user's own Mac + a paired Apple Watch with recorded workouts + a physical iPhone.
**It cannot be completed in a headless / CI / simulator-only environment**: HealthKit and Photos do
not run in the simulator, and the flagship flow needs real heart-rate series and real media shot
during a workout window.

## Context the implementer needs

- The app reads **completed** workouts via `HealthKitService` (`HKSampleQuery` over `.workoutType()`,
  per-workout `.heartRate`, latest `.restingHeartRate`), discovers media in the workout window via
  `PhotoLibraryService` (±90 s padding — an unvalidated guess, P5), and exports with `ReelExporter`
  (`AVMutableComposition` + `AVAssetExportSession`).
- Project is generated by XcodeGen from [`ios/App/project.yml`](../../../ios/App/project.yml): bundle
  id `com.snappet.app`, deployment iOS 18.0, HealthKit entitlement
  (`Snappet/Resources/Snappet.entitlements`), `HighlightEngine` SPM dependency.
- Usage strings already live in `Snappet/Resources/Info.plist` (Health share, Photos read, Photos
  add). `GENERATE_INFOPLIST_FILE: NO` — that plist is authoritative.
- Onboarding (P2) gates first launch: a value-first **"Connect Health & Photos"** screen requests
  Health then Photos on an explicit tap, with a `.limited`-access manual `PHPicker` fallback.
- `FeedbackStore` writes `highlight-feedback.jsonl` to the app's **Application Support** directory,
  appending one JSON object per `.proposed`/`.removed`/`.pinned`/`.reordered`/`.regenerated`/`.exported`
  event. This is the dataset the offline tuner (`experiments/feedback-replay/run.py`) consumes.
- Known runtime risk areas a type-check missed: HealthKit authorization is **not readable** (gate on a
  persisted flag, never query read-status); `AVAssetExportSession` Sendable/preset behaviour on device;
  the exporter currently **drops photos** (video-only stitch); the ±90 s media↔HR padding.

## Approach

- Generate + open the project on the user's Mac (`xcodegen generate && open Snappet.xcodeproj`), set a
  signing Team and (if needed) a unique bundle id, select the physical device, and Run.
- Walk the live flagship flow end to end on device against a **real** workout that has photos/videos
  shot during it: onboarding → grant Health + Photos → pull-to-refresh the workout list → open a
  workout → auto-built reel → Preview → optional pin/reorder/remove/regenerate → Share/export.
- Fix what breaks at runtime — signing, entitlements, plist strings, authorization sequencing, empty
  HR/media handling, export errors — keeping changes minimal and within existing files. **Do not**
  add platform imports to `HighlightEngine`; **do not** tune `HighlightConfig` from a single session.
- Confirm `highlight-feedback.jsonl` is written, pull it off the device, and run it through
  `experiments/feedback-replay/run.py <path>` so the loop is proven end to end.
- Capture honestly what was observed (HR picks plausible? media discovery working? export shareable?)
  to feed the **after-P1 decision gate** in the PLAN.

## Output

- A running build on a real device (no new feature scope beyond making the existing flow work).
- Targeted runtime fixes only, in the existing app sources / `project.yml` / `Info.plist` /
  entitlements as needed — each justified by a real on-device failure, not speculation.
- The first real `highlight-feedback.jsonl`, pulled off the device, and a one-line
  `feedback-replay` sanity run on it.
- [`ios/App/RUNBOOK-device.md`](../../../ios/App/RUNBOOK-device.md) followed/kept accurate.
- `decisions.md` entry: first on-device run — what was verified vs the type-check, any fix made, and
  whether the auto picks looked right (informs the after-P1 gate).

## Acceptance criteria

- [ ] `xcodegen generate` produces `Snappet.xcodeproj` from `project.yml` with no errors.
- [ ] The app **builds and runs on a physical iPhone** (full link + bundle + install + launch), signed
      with the user's Team.
- [ ] On first launch the **value-first onboarding** screen (P2) appears and Health + Photos are
      requested only on the explicit "Connect Health & Photos" tap — never silently on appear.
- [ ] Health prompt requests heart rate, workouts, and resting HR; Photos prompt appears (Full Access
      recommended; the `.limited` manual-picker fallback works if chosen).
- [ ] Pull-to-refresh lists **real** completed Apple Watch workouts; opening one with media shot during
      its window yields **auto-discovered clips** and an **auto-built reel** ranked by HR intensity.
- [ ] Share/export produces a real, **shareable `.mp4`** via the system share sheet.
- [ ] `highlight-feedback.jsonl` is written to Application Support and contains events from the
      session; it parses cleanly through `experiments/feedback-replay/run.py <path>`.

## Constraints

- On-device only; Health + media never leave the device. No backend, network, accounts, analytics.
- Requires the user's Mac + paired Apple Watch with real workouts + a physical iPhone — **not
  reproducible headless / in the simulator** (HealthKit + Photos are device-only).
- Keep `HighlightEngine` platform-free; keep the selector pluggable; don't hardwire HR-only.
- Don't change `HighlightConfig` knobs / selector weights off one session — that's P6 (replay tuning),
  recorded in `decisions.md`. Record runtime findings honestly: state exactly what device-ran.
