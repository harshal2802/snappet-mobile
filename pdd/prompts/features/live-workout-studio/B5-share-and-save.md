# Prompt: Share + save generated/edited videos to Photos (the video-studio finale)

**File**: pdd/prompts/features/live-workout-studio/B5-share-and-save.md
**Created**: 2026-06-01
**Project type**: Native iOS feature (Swift / SwiftUI) — code lands in this repo.
**Chain**: `live-workout-studio/PLAN.md` → Track B → **B5** (final phase; builds on B3 `VideoStudio`/clip
editor + B4 `SessionHighlightViewModel`/highlight reel). No successor.
**Source**: GitHub issue [#15](https://github.com/harshal2802/snappet-mobile/issues/15); `RESEARCH.md` §3.6.
**Context**: `pdd/context/project.md`, `conventions.md`, `decisions.md` (2026-05-31 ship-prep/privacy;
2026-06-01 B3 `VideoStudio`/`ClipEdit`, B4 bridge/`SessionHighlightViewModel`).

## Goal

Every generated/edited video — the **B3 edited clip** and the **B4 highlight reel** — can be **shared**
(system share sheet) or **saved to the Photos library**. The user's "all the videos generated by user
could be sharable or downloadable to local/Photos". On-device only — no upload/backend.

## Context the implementer needs

- The flagship reel app already has a top-level `ShareSheet` (a `UIViewControllerRepresentable` around
  `UIActivityViewController`) in `Features/Reel/ReelView.swift`. **GENERALIZE it** — move it to a shared
  location and reuse it from WorkoutTracker; do **not** write a second `UIActivityViewController` wrapper.
- `Services/VideoStudio.swift` (B3): `export(_ plan: EditPlan) async throws -> URL` renders the edited clip
  to a temp `.mp4`. `Services/ReelExporter.swift` (flagship): `export(_ plan: ReelPlan) async throws -> URL`
  renders the highlight reel. **Reuse both** to get a file URL — don't reimplement export.
- B3 `ClipEditorView`/`ClipEditorViewModel` and B4 `SessionHighlightView`/`SessionHighlightViewModel` are the
  two producers; the B4 VM already builds a `ReelPlan` to preview (keep it so Export can render the same reel).
- `Services/PhotoLibraryService.swift` requests **read-write** Photos auth for discovery; saving needs only
  **add-only** — a distinct, narrower grant.
- Layering rule: platform I/O lives in `Services/`; `HighlightEngine` stays platform-free (grep-verify).
  Modules don't nest a `NavigationStack` — share/save live on the existing sheets (sheets are fine).

## Approach

1. **`Services/MediaLibraryService.swift`** (stateless `Sendable`): `saveVideoToPhotos(_ url: URL) async
   throws` — request **add-only** auth (`PHPhotoLibrary.requestAuthorization(for: .addOnly)`), then
   `try await PHPhotoLibrary.shared().performChanges { PHAssetCreationRequest.forAsset().addResource(with:
   .video, fileURL: url, options: nil) }` (the async `performChanges` overload — no continuation needed).
   Typed `LocalizedError` (`.denied`/`.failed`). No bytes leave the device.
2. **Generalize `ShareSheet`** — move it out of `ReelView.swift` into `Features/Shell/ShareSheet.swift`
   (one component for the whole app target); the flagship reuses it unchanged.
3. **Pure `ExportShareState`** (`Features/WorkoutTracker/ExportShareState.swift`): an `Equatable` value-type
   state machine (`idle → exporting → exported(url) → saving(url) → saved(url)`, plus `failed(msg)`) with a
   reducer, so the transitions + the carried export URL + `isBusy`/`exportedURL` are **unit-testable with no
   AVFoundation/PhotoKit/UIKit** (the device-only export/save/share themselves are not). The rendered file
   URL is carried through `.exported`/`.saving`/`.saved` so share + save reuse the **single** render.
4. **Wire both producers** (views thin; I/O via the services):
   - **B3 clip editor** — `ClipEditorViewModel.export()` (`VideoStudio.export(EditPlan(edit))`) →
     `.exported`; `saveToPhotos()` → `MediaLibraryService`. A new "Export" control card in `ClipEditorView`:
     Export → Share + Save to Photos, with progress/`saved` feedback. A subsequent edit invalidates the
     export (`commit()` resets to `.idle`).
   - **B4 highlight** — `SessionHighlightViewModel` keeps `lastPlan` from `generate()`, adds `export()`
     (reuse `ReelExporter.export(lastPlan)`) + `saveToPhotos()`; a new Export/Share/Save section in
     `SessionHighlightView`, shown once a reel is generated. Re-generating resets the export.
5. **Privacy** — `NSPhotoLibraryAddUsageDescription` in the app Info.plist (add-only save, distinct from the
   read `NSPhotoLibraryUsageDescription`). `PrivacyInfo.xcprivacy` stays accurate: saving to the user's own
   library is on-device, so **no** data-collection claim is added.

## Acceptance criteria

- [ ] `MediaLibraryService.saveVideoToPhotos` requests **add-only** auth, saves via `performChanges` adding a
      `.video` resource, throws a typed `LocalizedError` on denied/failed; `Sendable`.
- [ ] One shared `ShareSheet` (no duplicate `UIActivityViewController` wrapper); the flagship reuses it.
- [ ] Both producers can Export → Share + Save the resulting `.mp4`, reusing `VideoStudio.export` /
      `ReelExporter.export`; an edit/re-generate invalidates a prior export.
- [ ] The export/share/save state logic is unit-tested in `SnappetTests` (transitions, carried URL, busy gates).
- [ ] No platform import added to `HighlightEngine` (`git diff ios/HighlightEngine` empty). Views thin; no
      nested `NavigationStack` (share/save ride the existing sheets).
- [ ] App + watch schemes build; `SnappetTests` + `WorkoutWalkthroughTests` green; `HighlightEngine` 18/18.

## Constraints

- Swift 6 strict concurrency: `@MainActor` UI; the `@Model` is snapshotted into `EditPlan` on the MainActor
  before crossing into `VideoStudio`; PhotoKit's auth + `performChanges` use their async overloads.
- On-device only — saving to the user's **own** Photos library is local; no upload/backend/accounts.
- State verification honestly: the service + the two wire-ins + Info.plist + build + the pure state tests are
  verified; the actual **Photos save + the share-sheet round-trip** need a **real rendered video on a device**
  (the sim has no Photos/video, so `VideoStudio`/`ReelExporter` resolve no `AVAsset` and produce nothing to
  save). A clean build is **not** a verified Photos save / share.
