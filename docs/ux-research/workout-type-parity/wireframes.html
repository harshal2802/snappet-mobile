Workout-type parity — every type logs like climbing

Real-looking wireframes for bringing Strength, Running, Dance & Other to the same entity → effort structure climbing already has: expandable entity cards, last-time prefill, a live stats ribbon, and a type-adaptive summary. Plus timed as an orthogonal axis — any set can be reps × weight and timed (8 × 60 kg · 0:42). Tokens are the real SnappetColor values; the iPhone scaffold matches the climbing wireframes. Plan & rationale in README.md.

Flow 1 · the parity centerpiece

Strength — add an exercise, then log sets under it (climb-card parity)

A strength exercise becomes a real entity card exactly like a climb: a rolled-up header (top set · volume · e1RM) that expands to its set list, last-time prefill, a one-tap quick-add stepper, and a footer with + Add set / ⏱ Time this set / ↻ Repeat. The hybrid add sheet keeps the fast bulk multi-select but lets you set a default sets × reps × weight per exercise.

Flow 2 · timed is an axis, not a type

Time any set — reps × weight and a timer on one effort

“⏱ Time this set” opens the same full-cover FOCUS timer climbing uses, generalized to any entity. A strength set keeps its reps × weight and gains a measured time-under-tension → the row reads 8 × 60 kg · 0:42 (the combined format climbing already ships). The standalone Timed type still owns structured hangboard / Tabata / EMOM runs.

Flow 4 · video & photos on every type

Clips & photos attach the same way — for every discipline

The capture pipeline is already discipline-agnostic: a clip you film mid-set auto-files to whichever effort was running at capture time (SessionMediaAssignment flattens all sets by completion time — it never looks at kind), and the manual SetMediaStrip files against (exerciseID, setIndex). Parity work is small: show the per-set strip on every set (today it’s on every climb attempt but only the last strength/timed set), and make the move/remove menu say “set / leg / attempt” per discipline.

The unifying model

Discipline (entity) × measurement axes (effort) — the spine

One generic SessionExercise (entity) → many SetLog (efforts). No rewrite — additive optionals only.

The model already hosts all kinds in one struct. The change replaces the monolithic 3-case SetKind with two orthogonal axes, both stored as additive Optionals on the existing Codable blobs (zero SwiftData migration, the documented invariant at WorkoutModels.swift:220-225):

① Discipline — on the entity
climb · strength · run · dance · timed · other → drives icon, add-sheet, card chrome, summary branch, rest-context.
② Measurement axes — on each effort
reps · weight · duration · distance/pace · outcome. A leaf populates any combination → “8 × 60 kg · 0:42” is just two axes present.
③ One card component
Extract climbSection → a discipline-parameterized EntitySection. Header chips, footer actions, rolled-up rollup supplied per discipline.

Proof it’s right: climbing’s SetMeasure.summary already renders a combined categorical + timed row (SetMeasure.swift:36), and RestTimerDefaults is already orthogonal across all three kinds. We’re generalizing two patterns the codebase has already validated — not inventing new infrastructure.
