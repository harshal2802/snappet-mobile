Four ways to offer Source / Routine / Type on the Gym Tracker History screen. The list is identical in all four — only the filter chrome differs, and with it how much history you can actually see without scrolling.

The problem (option A, shipped today): three stacked chip rows sit between the segmented control and the first session — about a third of the screen is chrome before any content. It also grows: every new routine name widens row 2, and any future facet adds a fourth row.

Constraint from prior feedback: Kilter's pull-down filter drawer hid search so well the tester never found it (kilter-ux-feedback prompt 04). Whatever replaces this must keep filtering visibly discoverable — an unlabelled icon alone is not enough.

C+ · the refined version

C's instinct is right — the default state should be your history, not a control panel. These four changes remove its weak points without giving that up.

1. A labelled button, not a bare icon. "Filters" sits at the trailing edge of the search row — the other "narrow this list" control — so it costs no extra vertical space, isn't lost among the nav-bar circles, and reads as a control rather than decoration. This is the specific fix for the Kilter discoverability failure.

2. The sheet live-applies at a medium detent. You see the list re-filter behind the sheet as you tap, so there's no "apply → dismiss → check → reopen" loop. The primary button reads "Show 12 sessions": it tells you the outcome before you commit to it.

3. Active filters are never invisible. A slim token row appears only while filtering, with per-token ✕ and Clear all — and filters reset when you leave the screen. A silently-persisted filter under a zero-chrome header would recreate the bug we just removed: History quietly hiding half of itself.

4. No dead ends. A filter that matches nothing offers "Clear filters" in place, rather than an empty list.
