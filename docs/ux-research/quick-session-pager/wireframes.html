Quick Session — full-screen pager

Redesign direction for the freeform Quick Session player: replace the single long scrolling list of expandable cards with a horizontal pager — one exercise per full screen, swiped L↔R in the order exercises were added. Each discipline gets its own purpose-built page. The current set/attempt owns the screen; previous efforts collapse into a quiet one-line "ghost ledger". Chrome is Liquid-Glass: floating translucent nav, exercise rail, and dock over an ambient discipline-tinted backdrop.

Pulse Coral — the one primary CTA per screen Workout ember — discipline wayfinding (strength/timed) Kilter amber — climbing wayfinding Azure — running wayfinding perfFresh — done / sent / recovered state
Flow A

The pager: overview → exercises → add, all one swipe apart

Page 0 is the session overview (stats + jump list + Finish). Every exercise is one full page, in added order. Swiping past the last exercise lands on the “+ Add” page, so growing the session is part of the same gesture. The exercise rail under the nav is the page indicator: tap any chip to jump, the current chip is tinted with its discipline accent.

Flow B

One purpose-built page per discipline

Same skeleton on every page — glass nav · rail · title+plan · current-effort hero · one coral CTA · ghost ledger · glass dock — but the hero is discipline-specific: outcome buttons for climbs, a ring for timed/intervals, distance+pace for runs. The ambient backdrop tint follows the discipline accent.

Flow C

Previous efforts: quiet by default, full ledger one pull away

The de-clutter rule: history never competes with the current set. Default state is the one-line ghost row (Flows A/B). Tapping it — or pulling up from it — opens a glass history drawer with the full ledger, per-set comparisons against last session, and edit/delete actions that today hide behind expanding cards.

Flow D

Planned sets: set the target, watch it fill, get nudged forward

Where the axis makes sense (strength · timed · run legs), each exercise carries an optional planned count. It defaults from last session, is edited by tapping “of N” in the plan row, and renders as the segment bar everywhere (page header, rail mini-count, overview rows). Completing the plan produces a gentle “done — swipe on” moment instead of trapping you in the page.

Flow E

Media on the page: record, shelf, deep-tap, guide photos

All existing media machinery re-homed into the pager. The dock’s 📷 records a live clip that auto-attaches to the current set/attempt (same ±90s auto-discovery). Each exercise page gets a media shelf — a one-row strip of thumbnails between the hero and the ghost ledger, only rendered when media exists so clean pages stay clean. Long-press keeps today’s reassign / remove / delete menu; tap opens the clip in the Studio. The exercise title’s ⓘ opens the downloaded guide-photo pack.

Why this shape — and what to sanity-check before building:
  • Clutter fix is structural: the old screen showed every exercise × every set at once; the pager shows one current effort, with density (history, stats, plan) demoted to drawer/overview layers.
  • Color contract holds: discipline accents only for wayfinding (rail, tags, segments, ambient tint); coral only on the single primary CTA; green/amber/red only for state (done, zones, deltas).
  • Gesture safety: all hero inputs are taps (steppers, outcome buttons) — nothing horizontal competes with the page swipe. Known risk to verify on-device: TabView(.page) snap feel (same concern as the Clips pager).
  • Everything shown maps to existing machinery: prefills (`LastSetLookup`), rest timer (Phase 7), interval runner (`StructuredTimedRunner`), clips (`RecordClipButton` + `SetMediaStrip` becomes the media shelf, same deep-tap menu), guide photos (prompt 108 pack), live HR chip — re-homed, not rebuilt. The only new model field is `plannedSets` on `SessionExercise`.
  • Open question: does the ✓-when-plan-done rail state need a “skipped” affordance (exercise added but abandoned), and should Finish warn on unfinished plans?
