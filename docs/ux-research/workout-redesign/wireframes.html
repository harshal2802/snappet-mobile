Flow 0 · the Pulse Pro system + the keystone model (E0)

Pulse Pro design system, new IA, and the discipline-propagation model

Before any screen, lock the rules every later flow obeys. Pulse Pro is three constraints: a score-first hero (one oversized rounded numeral per surface), a two-axis color contract (discipline accent = who/where, a green → amber → tomato performance ramp = how hard, coral reserved for the single primary CTA), and glass on chrome only (floating bars/ribbons/timers get .ultraThinMaterial; content cards stay flat on SnappetColor.surface with a hairline). The keystone (E0) is one additive model move — give RoutineExercise the same disciplineRaw + per-axis targets that SessionExercise already carries — and makeSession(from:) propagates it so the guided player, builder, save-as-routine, QR-share and planner all turn type-aware for free, migration-free. Tokens are literal SnappetColor values.

A

The two-axis color contract — accent ≠ effort, and coral is sacred

Color carries two independent meanings. Mixing them is the one cardinal sin: a workout is never "redder" because it was hard, and a PR is never "ember" because it happened in the gym.

① Discipline accent — WAYFINDING (who / where)

SnappetColor.coral is reserved: one coral element per screen — the primary action or a brand flourish (CelebrationBurst). It is not a discipline and not the top of the effort ramp.

The rule: accent answers "what discipline is this?", ramp answers "how hard was it?", coral answers "what's the one thing to tap?". Never let one axis borrow another's color.

Why two axes. Earlier drafts painted whole cards in the discipline accent, so "hard" and "climbing" fought for the same red. Splitting wayfinding (accent) from intensity (ramp) lets a single glance read both. Reuses the live HeartRateZone --z1..--z5 ramp and the Glass-HUD zone bands.
