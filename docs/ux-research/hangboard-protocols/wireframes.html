Hangboard protocols · load · any-frequency schedules

Your answers drawn out: (1) a schedule can repeat at any frequency, down to every few minutes; (2) load means real weight, either added on top of bodyweight or taken off with a pulley; (3) a rep can be timed or "until I tap done"; (4) protocols come as presets you can edit, and you can adjust them mid-run. The rule throughout: one plain-English summary, sensible defaults, and advanced options hidden until you need them.

Fixed first, no design needed: a protocol saved in a routine currently plays once per set, so a 3-set Max hang asks for 9 sets (confirmed in RoutineSessionBuilder.swift:91). After the fix, one routine block = one run of the protocol (frame 10).
Modular: load and self-paced reps are optional extras on the timed-protocol model. Every existing timed exercise, routine, backup and QR code reads exactly as before.

Your calls

Q1 · Load control. L1 direction chips + stepper (frame 2) · L2 one signed slider (2B). My pick: L1. It names "added weight" and "pulley assist" in plain words.
Q2 · Editing mid-run. R1 tap a chip → Adjust sheet, timer keeps running (frame 4) · R2 pause to reveal values (4B). My pick: R1. It's always visible, and the clock never stops.
Q3 · Saving a mid-run change. Ask at the end with Keep for next time / Just this once (frame 6), vs. always keeping it, vs. never keeping it. My pick: ask, and only when something changed.
Q6 · Protocols in routines. A block is a copy of a preset (frame 10B), and editing a preset asks whether to update routines (10C), vs. blocks linked to the preset so they always follow it. My pick: copy + ask. Linking changes routines silently and breaks QR sharing, since the other phone doesn't have your preset. Scheduling stays on routines; "Schedule" on a lone protocol makes a one-block routine.
Q7 · Force sensor. Auto start/stop reps on by default when a Tindeq is connected (frame 11), a target band from "% of max" (12), and a measured max test per hand (13). My pick: as drawn, with everything still working exactly the same when no sensor is connected. Built as a generic "force sensor" so other boards (PitchSix, Entralpi…) can be added later.
Q8 · Connecting during a workout. Offer to connect before the first rep (12B) and any time mid-run (12C), prominently only when a known sensor is nearby, and fall back to the timer without stopping if it drops (12D). My pick: as drawn. Never-paired users only get the quiet ⋯ menu item, so nobody without a sensor gets nagged.
Q9 · Exact weights. Tap-to-type on every weight (frame 15) plus a ± step choice in Settings (16). My pick: as drawn. It's small, and ships first with the bug fix, since it helps every workout today.
Q5 · Hands. Both (default) / One hand with Alternate · Left first · Left only · Right only (frame 2C), reps counted per hand, and hand logged per set (5B). My pick: as drawn. Also track grip type / edge size (e.g. 20 mm half crimp)? It's the same kind of optional field, and it only earns its place if you want history comparable by grip.
Q4 · Several a day and Habits. A day counts as done after N sessions (default 1, frame 7). My pick: default 1, so a grease-the-groove plan doesn't break your streak over one missed slot.
