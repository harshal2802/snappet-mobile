Wardrobe · Richer add form

Device feedback, 2026-08-02: “We can make add to closet form more feature rich… brand, size, online link, price bought, current price if online link is provided, allow a way to add custom value in all the fields which have dropdown and also update same value in related dropdown for future.” P3 of the closet trio — P1 (photo pipeline) and P2 (multi-photo) are shipped.

Designed against your real closet, not a guess. Pulled from MrRobot: material is already being used as a brand field — Uniqlo 32, Lululemon 30, Temu 10, Amazon 5, Zara/Nike/Adidas 2 each — and 41 of 95 values carry stray whitespace, so 'Lululemon ' and 'Lululemon' are two different values today. Size is typed into the item name 10× (“Black tank top size M”), and graphic-tee prints go there too (“Illenium ‘Amber shores Cancun 2021’”). So P3 is not just new empty fields — it has to move the data you already typed into the right ones.
In scope. Brand · size · product link · price paid · current price (fetched on demand, parsed by Apple Intelligence, with a “checked on” stamp). Custom values in every dropdown, remembered for reuse, each mapped to a nearest built-in so the outfit composer keeps scoring. A one-time guided cleanup that proposes brand/size moves and never rewrites silently.
Not in scope: price history charts, retailer accounts, stock/restock alerts, barcode scanning, and automatic background price polling (checks are user-initiated only).

Behind the glass
Calls worth arguing with

Storage. New optional fields on WardrobeItem: brand, size, productURL, currentPrice, currentPriceCheckedAt (cost already exists as price-paid). Plus a small WardrobeVocabulary model — one row per remembered custom value: field, value, mapsToRaw (the nearest built-in, nil for unscored fields), useCount. All inline-defaulted / optional, no relationships, so the CloudKit posture from prompt 01 holds and this is a zero-migration schema change.

Why custom values need a “behaves like”. OutfitComposer scores color harmony over a closed 16-family wheel and formality over a 0–5 style scale. A free-string color has no hue and no formality, so it would silently drop out of every suggestion. Mapping once keeps the composer exact and the vocabulary open — this is the reason the P2 photo roles stayed closed while these open up.

The price fetch is the one network call in the whole app. Everything else in Snappet is on-device. It is user-initiated only, one request per tap, no background polling, no accounts. The HTML is parsed locally by Apple Intelligence (same #if canImport(FoundationModels) + availability contract as the tag sharpener) with a plain JSON-LD/OpenGraph regex floor when FM is unavailable — so it degrades instead of failing. A failed check keeps the last known price and its old timestamp.

Two things to push back on if you disagree: (1) the cleanup is opt-in and reviewable rather than automatic — it is your data and the brand/print distinction genuinely isn’t machine-decidable; (2) material is kept rather than repurposed, because a few values really are fabrics and silently redefining a field is how you lose data.
