Your PDD workflow, run by a team

Each step of a PDD job gets an owner. The planner writes the prompt, two builders implement it in parallel, the reviewer runs the gates, and the scribe keeps context true. You only see the request and the final report.

Skill + agentsThe lead is a skill in your main session. The five roles are agents it launches.
One roster filepdd/context/team.md holds every Snappet-specific rule, so the agent files stay generic.
Belongs in pdd-skillMost roles already are pdd-skill workflows. Snappet runs it first; then it moves upstream.

Figure 5 · versioning

Each kind of file changes in its own way

Git holds every version. The files only say what state they're in and what replaced them.

Feature promptpdd/prompts/features/
draft→active→shipped→superseded Edit freely until it ships. After that it's locked; a change of direction is a new prompt with supersedes:.
Decision notepdd/context/decisions/
active→superseded Only ever added. The old note keeps its text; only its status changes, and it links to the new one.
Context noteproject.md · modules/*.md
always "now" Rewritten in place to match reality. To see it at a past release: git show ios/v0.4.0-23:pdd/context/modules/festival.md.
Screen notepdd/context/screens/
wireframed→built→shipped→retired Text is "now"; its screenshots are captured per release, so the history is visual (figure 7).
