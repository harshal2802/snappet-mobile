Snappet Mobile · agent team

Turning the agent company into a skill

The team is the PDD lifecycle with a different worker assigned to each step. So the cleanest home for it is a new workflow inside the PDD skill, with the Snappet-specific team files kept in the repo.

Short answer: yes to both, split in two layers.

The PDD skill holds the generic playbook ("how a team runs a PDD job"). The repo holds who is on the team and what each role may touch. A separate standalone skill would repeat the PDD rules and drift from them.

First, the two building blocks

A skill is a playbook. An agent is a worker.

Skill · .claude/skills/<name>/SKILL.md
your conversation
+ the playbook loaded into it
one brain, follows the steps
  • Instructions loaded into the current session
  • Triggered by /name or when the task matches
  • Portable: works in any repo
Agent · .claude/agents/<role>.md
lead session
pmios-engqascribe
separate brains, run in parallel
  • Own context window, tools and model
  • Write access limited to its own paths
  • Project-specific by nature

They combine: a skill can tell the lead session which agents to launch and in what order. That is what "team mode" is.

One job, end to end

"Add a weekly 'past you' diff to Home"

1

You ask the CTO

One sentence. The CTO reads pdd/context/ and splits it into one-PR jobs.

2

PM writes the feature prompt

From the template, with acceptance criteria and linked decisions. The CTO checks it before any code.

3

Engineers build in parallel

Each in its own git worktree, each limited to its own folders.

ios-eng → ios/**android-eng → android/**
4

QA runs the gates

Real commands, output pasted. On Linux only engine and Android tests run, so iOS is marked "not verified here".

make engine-testmake ios-test-unitmake android-test
5

Scribe updates the docs

Knowledge graph node and edge, decisions.md, project.md.

6

You approve

One report: what shipped, test output, open questions. Pushes and TestFlight uploads stay with you.

The three ways to package it

Options compared

A · agents only

Role files in the repo

  • Fastest to start
  • Orchestration rules live in the CTO file, so they don't carry to other projects
B · new skill

Standalone "dev team" skill

  • Portable
  • Restates the PDD prompt and context rules, so the two can drift
C · recommended

Team mode in the PDD skill + role files in the repo

  • One source of truth for the lifecycle
  • Any PDD project can scaffold a team
  • Needs edit access to the PDD skill

If the PDD skill is the read-only built-in version, option C still works as a small project skill in .claude/skills/pdd-team/ that says "follow the PDD skill, plus these team steps". It can move upstream later.
